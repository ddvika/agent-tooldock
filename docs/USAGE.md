# Как использовать Agent ToolDock

[README](../README.md) · [English overview](../README.en.md)

## Локальный запуск

Нужен Node.js 22 или новее. Распакуйте проект и откройте его папку в терминале. Команды выполняются из корня проекта.

```sh
node --version
npm test
npm run demo
```

Для поиска по вложенному реестру достаточно исходников и Node.js. Содержимое реестра загружается из `data/catalog.json`. Зависимости и ключи внешних сервисов для поиска не нужны.

## CLI

Команды `search`, `get` и `stats` выводят JSON. Справка доступна через `--help`.

```sh
node src/cli.mjs --help
node src/cli.mjs stats
node src/cli.mjs search ВкусВилл --protocol MCP
node src/cli.mjs get if-061
```

### Примеры задач

Найти подключения, поддерживающие оформление заказа в личном сценарии.

```sh
node src/cli.mjs search --audience personal --stage order
```

Найти официальные MCP с самостоятельным получением доступа.

```sh
node src/cli.mjs search --protocol MCP --provenance official --access self_serve
```

Найти API для собственного умного дома.

```sh
node src/cli.mjs search "Яндекс Умный дом" --protocol API
```

Найти A2A-подключения.

```sh
node src/cli.mjs search --protocol A2A
```

### Как устроен текстовый поиск

Поиск сопоставляет слова с названием сервиса, названием подключения, разделом, описанием и списками функций. Регистр не учитывается, `ё` нормализуется в `е`. Несколько слов соединяются условием «все слова найдены». Для отдельных русских слов предусмотрены простые соответствия, например `корзина` и `корзину` ищутся по основе `корзин`.

Длинное поручение лучше преобразовать в короткие ключевые слова и фильтры. MCP-агент может сделать это при выборе аргументов инструмента. Для описаний на русском используйте русские запросы. Поиск по реестру не выполняет перевод или семантическую оценку текста.

## Подключение через MCP

В MCP-клиенте с поддержкой локальных stdio-серверов укажите команду запуска и абсолютный путь к `src/stdio.mjs`.

```json
{
  "mcpServers": {
    "agent-tooldock": {
      "command": "node",
      "args": ["/absolute/path/agent-tooldock/src/stdio.mjs"]
    }
  }
}
```

Структура экрана и файла настройки зависит от клиента. В Windows можно использовать путь вида `C:/projects/agent-tooldock/src/stdio.mjs`. Если графическое приложение не находит Node.js, замените `node` абсолютным путём к его исполняемому файлу.

Сервер читает JSON-RPC-сообщения из stdin и отправляет ответы в stdout, по одному сообщению на строку. При запуске через MCP-клиент процесс ожидает обращения клиента. Он поддерживает обнаружение сервера, инициализацию, список инструментов и их вызов.

### Инструменты

| Инструмент | Аргументы | Результат |
| --- | --- | --- |
| `find_connections` | Параметры поиска из таблицы ниже | Число совпадений, пагинация, краткие карточки с функциями, условиями и документацией |
| `get_connection` | `id` | Полная запись и все исходные поля |
| `catalog_stats` | Пустой объект | Числа по сервисам, протоколам, аудиториям и направлениям |

Пример аргументов для `find_connections`.

```json
{
  "audience": "personal",
  "stage": "order",
  "provenance": "official",
  "limit": 10
}
```

Получить полную карточку найденного подключения через `get_connection`.

```json
{"id": "if-061"}
```

### Пример поручения

> Подбери сервис для управления моим умным домом. Найди официальные подключения в реестре, открой полные карточки и объясни, какие устройства и действия доступны, как получить доступ и где находится документация.

Результат поиска — записи реестра. Для вызова функций выбранного провайдера требуется отдельная настройка его API, MCP или A2A и необходимых доступов.

## Фильтры

В CLI название фильтра начинается с `--`. В MCP передавайте эти же имена как поля объекта.

| Параметр | Значения и смысл |
| --- | --- |
| `query` | Название или ключевые слова, до 200 символов. В CLI передаётся позиционным аргументом после `search`. |
| `protocol` | `API`, `MCP`, `A2A` |
| `audience` | `personal`, `business`, `tools` |
| `access` | `self_serve`, `conditional` |
| `provenance` | `official`, `community` |
| `stage` | `need`, `search`, `compare`, `prepare`, `order`, `pay`, `after`, `service` |
| `action` | `information`, `preparation`, `digital_action`, `physical_action`, `unknown` |
| `sector` | Точное название направления из `catalog_stats` |
| `limit` | От 1 до 50, по умолчанию 10 |
| `offset` | От 0 до 10 000, по умолчанию 0 |

Записи могут подходить нескольким аудиториям. Фильтр `personal` использует личные этапы `consumer_stages`, `business` — бизнес-этапы `business_stages`. В текущем срезе личные сценарии найдены у 59 подключений, в том числе оформление заказа — у 8, оплата — у 5.

При совместном указании `audience` и `stage` проверяется этап для выбранной аудитории. В бизнес-сценарии `order` может означать обработку уже поступившего заказа. Для выбора сервиса, через который личный агент сможет оформить заказ, укажите оба фильтра `--audience personal --stage order`.

`self_serve` означает найденный официальный путь получения доступа без обязательного корпоративного договора или платного плана. Регистрация, OAuth, квоты и комиссии всё ещё могут быть частью условий. У `conditional` изучите `connection_conditions` и `limitations`.

`official` указывает на подключение от владельца сервиса, `community` — на стороннюю реализацию. Для выбора подходящего способа доступа используйте также документацию и авторство конкретной записи.

### Пагинация

В ответе есть `total`, `offset`, `limit` и `next_offset`. Для следующей страницы передайте значение `next_offset`. Значение `null` обозначает конец выдачи.

```sh
node src/cli.mjs search --protocol API --limit 50 --offset 0
node src/cli.mjs search --protocol API --limit 50 --offset 50
```

## JSON и CSV

Полный реестр находится в [data/catalog.json](../data/catalog.json). Табличное представление доступно в [data/catalog.csv](../data/catalog.csv).

Чтобы обновить CSV после изменения JSON, выполните команду из корня проекта.

```sh
npm run export
```

JSON подходит для интеграции в приложения и передачи агенту, который умеет читать файлы. CSV удобен для таблиц и анализа. Изучите выбранную запись полностью перед подготовкой интеграции.

### Основные поля записи

| Группа | Поля |
| --- | --- |
| Идентификация | `id`, `name`, `protocol`, `connection_title`, `sector` |
| Функции | `read_functions`, `prepare_functions`, `write_functions` |
| Сценарии | `consumer_stages`, `business_stages`, `action_class` |
| Доступ | `provenance`, `access`, `connection_conditions`, `auth_note` |
| Ограничения | `limitations`, `order_status`, `pay_status` |
| Источники | `url`, `evidence_urls`, `condition_evidence_urls`, `action_evidence_urls` |
| Дата и оценка | `checked_at`, `assessment_basis`, `assessment_quality` |

Набор дополнительных полей различается между записями. Пустое значение отражает отсутствие заполненного сведения в этом срезе.

## Методология и границы

Срез подготовлен по публичной документации на 7 ноября 2026 года. Исходное исследование рассмотрело 424 компании и продукта. В реестр включены 232 сервиса с найденными описаниями подключений.

Единица учёта — один сервис и один протокол. Поэтому API и MCP одного сервиса считаются разными записями. Всего в текущем срезе 312 подключений. Функции одного протокола не переносятся автоматически на другой.

Карточки разделяют получение информации, подготовку и выполнение действий. Создание корзины, счёта или ссылки описывается как подготовка. Для оформления заказа и оплаты в личном сценарии нужны отдельные подтверждения в документации.

В ходе исследования проверялись открытые описания. Реальное подключение к каждому сервису, выдача доступов и операции у провайдеров не тестировались. Перед использованием сверяйте условия с первичными источниками. Отсутствие записи или подтверждённой функции описывает пределы изученной выборки.

Тесты проекта проверяют целостность данных, фильтры, пагинацию и работу локального MCP. Они не обращаются к внешним провайдерам.

## Обновление реестра

Исправляйте источник данных `data/catalog.json`, приложив первичный источник и дату проверки. После изменений выполните экспорт и тесты. Порядок внесения изменений описан в [CONTRIBUTING.md](../CONTRIBUTING.md).

```sh
npm run export
npm test
```
